# Основные возможности lib-monitor

Библиотека `lib-monitor` предоставляет комплексное решение для мониторинга и управления ресурсами Astra. Ниже приведено детальное описание ключевых функциональных блоков.

## 1. Мониторинг DVB-тюнеров

Система обеспечивает полный контроль над физическими и виртуальными DVB-адаптерами:
*   **Динамическое управление**: Инициализация и запуск тюнеров "на лету" без перезагрузки всего процесса Astra.
*   **Метрики качества**: Сбор данных в реальном времени:
    *   `Signal`: Уровень сигнала в dBm или процентах (зависит от драйвера).
    *   `SNR`: Соотношение сигнал/шум.
    *   `BER`: Bit Error Rate (количество ошибок до коррекции).
    *   `UNC`: Uncorrected blocks (блоки, которые не удалось восстановить).
*   **Побитовый анализ**: Проверка состояния фронтенда через `bit32.band`:
    *   `Lock (0x10)` — захват сигнала.
    *   `Signal (0x01)` — наличие сигнала.
    *   `Carrier (0x02)` — наличие несущей.
    *   `Sync (0x08)` — синхронизация.
*   **Управление ресурсами**: Автоматическое инкрементирование и декрементирование счетчика `channels` в Astra. Это позволяет нескольким мониторам или стримам использовать один и тот же адаптер без конфликтов.
*   **Устойчивость**: Пройдены тесты **Ultra-Extreme**, подтверждающие стабильность при "дребезге" сигнала (быстрое пропадание/появление) и некорректных ответах от драйверов.

## 2. Мониторинг каналов

Поддержка глубокого анализа медиа-потоков:
*   **Типы мониторов**:
    *   `input`: Мониторинг непосредственно на входе (до обработки).
    *   `output`: Мониторинг на выходе канала (после демультиплексирования и дешифрования).
    *   `ip`: Прямой мониторинг UDP/RTP/HTTP потоков без создания полноценного канала Astra.
*   **Анализ MPEG-TS**:
    *   Отслеживание `CC Errors` (Continuity Counter) для обнаружения потерь пакетов.
    *   Отслеживание `PES Errors` и ошибок скремблирования (`Scrambled`).
    *   Расчет битрейта для каждого PID и суммарного битрейта потока.
*   **Chaos Testing**: Система устойчива к массовому пересозданию каналов (Churn) и резким изменениям структуры потока (изменение набора PID).

## 3. Мониторинг системных ресурсов

Библиотека выступает в роли легковесного агента мониторинга для самого процесса Astra:
*   **Процессор (CPU)**: Разделение на `User` и `System` время. Использование `os.clock()` обеспечивает микросекундную точность.
*   **Память (RAM)**:
    *   `RSS`: Реальное потребление физической памяти.
    *   `Virtual`: Виртуальный размер процесса.
    *   `Lua GC`: Объем памяти, занятый объектами Lua.
*   **Диагностика утечек**: Отслеживание `lua_delta` (изменение памяти между тиками) и `lua_post_gc` (минимум памяти после принудительной сборки мусора).
*   **Сетевые интерфейсы**: Получение списка IP-адресов и MAC-адресов через `utils.ifaddrs()`.
*   **Автоматические алерты**: Генерация системных событий при превышении порогов (например, CPU > 90%).

## 4. Система подписок и событий

Высокопроизводительная шина событий (`EventDispatcher`):
*   **Многоканальность**: Доставка через Webhooks (HTTP), WebSocket, системный лог или Lua-коллбэки.
*   **Smart Emit**: Если у подписчика нет сложных фильтров, событие доставляется мгновенно, минуя очередь, что снижает задержку.
*   **LVC (Last Value Cache)**: Новые подписчики мгновенно получают последнее состояние объекта, не дожидаясь следующего обновления данных.
