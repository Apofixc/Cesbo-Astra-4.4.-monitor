# Оптимизация производительности

Библиотека `lib-monitor` спроектирована для работы в высоконагруженных средах Astra, где критически важно минимизировать влияние мониторинга на основной процесс стриминга.

## 1. Управление памятью и Table Pooling

Одной из главных проблем Lua в долгоживущих процессах является нагрузка на Garbage Collector (GC).
*   **Table Pool**: Система переиспользования таблиц. Вместо создания новой таблицы для каждого события или метрики, библиотека берет свободную таблицу из пула и возвращает её обратно после использования.
*   **O(1) защита**: Мгновенная проверка на двойное высвобождение (Double Release) через внутренние маркеры.
*   **Кастомные очистители**: Возможность регистрации специфических функций очистки для разных типов данных.
*   **Преаллокация**: Возможность заранее создать необходимое количество таблиц для критических участков кода.

## 2. Оптимизация шины событий

*   **Zero-Closure Path**: При рассылке уведомлений минимизировано создание временных замыканий (closures).
*   **Круговые буферы**: Использование круговых буферов для очередей событий и LVC, что исключает дорогостоящие операции сдвига элементов массива.
*   **Hybrid LVC**: Кэширование последних состояний одновременно в виде Lua-таблиц и готовых JSON-строк. Это позволяет мгновенно отвечать на HTTP/WebSocket запросы без повторной сериализации.

## 3. Эффективная фильтрация и маршрутизация

*   **JIT-фильтрация с инлайнингом**: Автоматическая компиляция условий фильтрации в Lua-код с встраиванием (inlining) путей доступа к данным. Это исключает вызовы функций-аксессоров в горячем цикле.
*   **Decision Tree Routing**: Маски событий (Wildcards) организуются в дерево решений. Это позволяет находить всех подходящих подписчиков за один проход по строке типа события, независимо от количества активных масок.

## 4. Адаптивная обработка и Load Shedding

*   **Адаптивные тики**: Автоматическое увеличение лимитов обработки событий (Batch Limit) при росте нагрузки на очереди.
*   **Load Shedding**: При заполнении очередей более чем на 90% система начинает отбрасывать низкоприоритетные события, предотвращая лавинообразный рост потребления памяти и задержек.
*   **Ленивая сериализация**: Кодирование данных в JSON происходит только один раз при необходимости и кэшируется для всех подписчиков.

## 5. Системные оптимизации

*   **Парсинг /proc**: Оптимизированный парсинг системных файлов с ранним выходом и использованием пула строк для минимизации I/O и аллокаций.
*   **Микросекундная точность**: Использование `os.clock()` для прецизионного расчета загрузки CPU без обращения к тяжелым системным вызовам времени.
*   **Оптимизированное логирование**: Формирование строк лога происходит только в том случае, если уровень логирования позволяет вывод сообщения.
