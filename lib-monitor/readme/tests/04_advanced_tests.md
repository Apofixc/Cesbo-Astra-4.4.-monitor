# Продвинутые сценарии тестирования (Advanced Scenarios)

Данный уровень проверяет динамическое поведение системы, управление дешифрацией и устойчивость к повреждению данных.

## 1. Динамическое управление (Hot-Reload)

### Сценарий "Обновление на лету"
*   **Что проверяем:** Способность системы применять изменения конфигурации без перезапуска.
*   **Действие:** Вызов `update_parameters` для работающего монитора.
*   **Верификация:**
    1.  Обновление внутренних полей конфигурации монитора.
    2.  Синхронизация параметров с работающим экземпляром Astra (например, `cc_limit`).
    3.  Изменение интервалов опроса в планировщике.
*   **Результат:** [SUCCESS] Система корректно адаптируется к новым параметрам в runtime.

## 2. Управление дешифрацией (CI/CAM)

### Сценарий "PNR Management"
*   **Что проверяем:** Взаимодействие с CI-слоем Astra через метод `ca_set_pnr`.
*   **Действие:** Запуск и остановка мониторинга DVB-адаптера с включенным параметром `cam`.
*   **Верификация:** Проверка вызовов системного API для добавления/удаления программ из списка дешифрации.
*   **Результат:** [SUCCESS] Логика управления PNR интегрирована в жизненный цикл монитора.

## 3. Устойчивость к повреждению данных (Persistence Integrity)

### Сценарий "Битый реестр"
*   **Что проверяем:** Поведение системы при повреждении файла `subscribers.json`.
*   **Действие:** Подмена файла на невалидный JSON (синтаксические ошибки).
*   **Верификация:**
    1.  Отсутствие критического краха при загрузке.
    2.  Автоматический сброс реестра в безопасное (пустое) состояние.
    3.  Возможность продолжения работы и регистрации новых подписок.
*   **Результат:** [SUCCESS] Система защищена от поврежденных файлов конфигурации.

## 4. Экстремальное логирование (Logger Pressure)

### Сценарий "Шторм ошибок"
*   **Что проверяем:** Влияние массового вывода логов на производительность системы.
*   **Действие:** Эмиссия 10,000+ записей в секунду.
*   **Верификация:**
    1.  Отсутствие блокировок основного потока Astra (Time-Slicing).
    2.  Стабильность потребления памяти.
    3.  Корректная работа кольцевого буфера (вытеснение старых записей).
*   **Результат:** [SUCCESS] Логгер сохраняет работоспособность и не дестабилизирует систему при перегрузках.
