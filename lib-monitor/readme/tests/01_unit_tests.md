# Модульное тестирование (Unit Tests)

Данный уровень тестирования проверяет каждый модуль библиотеки в полной изоляции. Все внешние зависимости Astra и другие модули библиотеки заменяются на "заглушки" (Mocks).

## 1. Инфраструктурные модули

### Менеджер модулей (ModuleManager)
*   **Что проверяем:**
    *   Регистрация и ленивая загрузка модулей.
    *   Автоматическое разрешение графа зависимостей.
    *   Обнаружение циклических зависимостей (например, A -> B -> A).
    *   Изоляция глобальных зависимостей Astra.
*   **Обработка некорректных данных:**
    *   Попытка регистрации модуля с nil-именем или некорректным путем.
    *   Загрузка модуля, чьи зависимости не зарегистрированы.
*   **Стресс-сценарии:**
    *   Массовая регистрация сотен модулей и проверка скорости построения графа.

### Планировщик (Scheduler)
*   **Что проверяем:**
    *   Точность выполнения периодических задач.
    *   Логика бинарной кучи (Min-Heap): задача с ближайшим временем запуска всегда в корне.
    *   Динамическое изменение интервалов "на лету".
*   **Обработка некорректных данных:**
    *   Добавление задач без callback-функции.
    *   Установка отрицательных или нулевых интервалов.
*   **Стресс-сценарии:**
    *   Работа с 1000+ активными задачами.
    *   Удаление задачи из её собственного обработчика ("самоубийство").

### Диспетчер событий (EventDispatcher)
*   **Что проверяем:**
    *   Маршрутизация событий по именам и маскам (Wildcards).
    *   Работа кэша последних значений (LVC).
    *   Соблюдение приоритетов (Critical события обрабатываются первыми).
*   **Обработка некорректных данных:**
    *   Эмиссия событий с nil-данными.
    *   Подписка на некорректные паттерны масок.
*   **Стресс-сценарии:**
    *   Шторм событий (10,000+ эмиссий) и замеры скорости очистки очереди.

### Пул таблиц (TablePool)
*   **Что проверяем:**
    *   Эффективность захвата (`get`) и возврата (`release`) таблиц.
    *   Глубокая рекурсивная очистка вложенных структур.
    *   Автоматический дренаж (очистка) неиспользуемых пулов.
*   **Обработка некорректных данных:**
    *   Защита от двойного освобождения одной таблицы.
    *   Возврат в пул таблиц, не принадлежащих ему.
*   **Стресс-сценарии:**
    *   200,000+ операций в секунду с замером стабильности памяти.

## 2. Мониторы и Репозитории

### Репозитории (Repositories)
*   **Что проверяем:**
    *   Регистрация и поиск мониторов по ID.
    *   Автоматическое восстановление (Auto-recover) при "тишине" данных.
    *   Механизм Watchdog для проверки функционального здоровья.
*   **Обработка некорректных данных:**
    *   Регистрация дубликатов имен.
    *   Поиск по nil-ключам.

### Мониторы (Monitors)
*   **Что проверяем:**
    *   Полный жизненный цикл (IDLE -> RUNNING -> STOPPED).
    *   Корректность формирования JSON-отчетов.
    *   Синхронизация параметров через хуки.
*   **Обработка некорректных данных:**
    *   Подача поврежденных MPEG-TS или DVB метрик.
    *   Экстремальные значения (SNR > 100%, отрицательный битрейт).
