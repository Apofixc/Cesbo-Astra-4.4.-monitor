# Детальная спецификация тестов библиотеки lib-monitor

В данном документе приведено подробное описание каждого файла тестов, включая проверяемые функции, сценарии обработки некорректных данных и стресс-тестирования.

## 1. Модульное тестирование (Unit Tests)
*Проверка логики отдельных модулей в изоляции с использованием моков.*

### Инфраструктура и Ядро
*   **adapter_test.lua:**
    *   *Функции:* `dvb_tuner_monitor`, `stop_dvb_monitor`.
    *   *Некорректные данные:* Проверка отказа при отсутствии обязательных параметров (имя адаптера), обработка невалидных типов.
    *   *Стресс:* Нагрузочный тест функции поиска монитора (100,000 операций).
*   **base_monitor_test.lua:**
    *   *Функции:* Жизненный цикл (`new`, `pause`, `resume`, `destroy`), кэширование JSON.
    *   *Некорректные данные:* Проверка поведения при передаче пустых конфигураций, обработка ошибок в хуках обновления.
    *   *Стресс:* Замер производительности извлечения статуса из кэша (100,000 операций).
*   **event_dispatcher_test.lua:**
    *   *Функции:* `emit`, `subscribe`, `get_last_values`.
    *   *Некорректные данные:* Эмиссия событий с nil-данными, подписка на несуществующие маски.
    *   *Стресс:* Массовая эмиссия (10,000 событий) и замеры скорости обработки очереди.
*   **scheduler_test.lua:**
    *   *Функции:* `add_task`, `remove_task`, `_tick`.
    *   *Некорректные данные:* Попытка добавления задач с некорректными интервалами или без callback-функций.
    *   *Стресс:* Работа планировщика с 1000+ активными задачами одновременно.
*   **table_pool_test.lua:**
    *   *Функции:* `get`, `release`.
    *   *Некорректные данные:* Защита от двойного освобождения таблицы, возврат в пул таблиц неверного типа, обработка nil.
    *   *Стресс:* Интенсивный цикл захвата/освобождения (200,000 операций), проверка глубокой рекурсивной очистки.
*   **module_manager_test.lua:**
    *   *Функции:* `register_module`, `load_modules`.
    *   *Некорректные данные:* Регистрация модулей с опасными путями, обнаружение циклических зависимостей (A->B->A).
    *   *Стресс:* Массовая регистрация и валидация графа зависимостей.
*   **subscription_manager_test.lua:**
    *   *Функции:* `subscribe`, `unsubscribe`, `publish_event`.
    *   *Некорректные данные:* Подписка с некорректными конфигами (отсутствие host/port для HTTP), обработка ошибок в пользовательских callback.
    *   *Стресс:* Массовая подписка (5,000 операций) и высокоскоростная публикация событий (10,000 операций).

### Хранилища (Repositories)
*   **base_repository_test.lua:**
    *   *Функции:* `register`, `unregister`, `find`, `update_settings`.
    *   *Некорректные данные:* Поиск несуществующих объектов, регистрация объектов без необходимых методов (destroy).
    *   *Стресс:* Интенсивная регистрация и удаление мониторов (5,000 операций).
*   **channel_repository_test.lua / dvb_repository_test.lua:**
    *   *Функции:* `find_by_adapter`, `count`.
    *   *Некорректные данные:* Поиск по некорректным именам адаптеров, работа с пустыми реестрами.
    *   *Стресс:* Массовый поиск в реестре из сотен объектов.

### Мониторы и Логика
*   **channel_monitor_test.lua:**
    *   *Функции:* `new`, `start`, `_on_astra_data`.
    *   *Некорректные данные:* Подача поврежденных MPEG-TS метрик (nil в total, отсутствие on_air).
    *   *Стресс:* Высокоскоростная обработка данных от анализатора (50,000 операций).
*   **tuner_monitor_test.lua:**
    *   *Функции:* `_on_astra_data` (DVB статус).
    *   *Некорректные данные:* Обработка некорректных битовых масок статуса, экстремальные значения SNR/BER.
    *   *Стресс:* Имитация шторма обновлений статуса тюнера.
*   **resource_monitor_test.lua:**
    *   *Функции:* `check`.
    *   *Некорректные данные:* Имитация отсутствия сетевых интерфейсов, ошибки чтения `/proc/stat`.
    *   *Стресс:* Частые проверки ресурсов с минимальным интервалом.
*   **filter_engine_test.lua:**
    *   *Функции:* `match` (логика фильтрации).
    *   *Некорректные данные:* Проверка поведения при отсутствии полей в данных, некорректные операторы сравнения, ошибки в JIT-скомпилированных фильтрах.
    *   *Стресс:* Высокоскоростная фильтрация (100,000 матчей в секунду).
*   **logger_test.lua:**
    *   *Функции:* `info`, `error`, `with_error` (контексты).
    *   *Некорректные данные:* Передача нестроковых сообщений, ошибки форматирования строк (bad format), переполнение буфера логов.
    *   *Стресс:* Интенсивное логирование (100,000 записей) и проверка влияния на память.
*   **utils_test.lua / wildcard_test.lua:**
    *   *Функции:* `split`, `ratio`, `compile_pattern`, `match`.
    *   *Некорректные данные:* Разделение пустых строк, деление на ноль, некорректные символы в масках.
    *   *Стресс:* Массовое сопоставление строк с сотнями паттернов одновременно.
*   **ws_subscriber_test.lua:**
    *   *Функции:* `init`, `broadcast_raw`.
    *   *Некорректные данные:* Регистрация клиентов с nil-объектами, отправка некорректного JSON.
    *   *Стресс:* Массовая рассылка уведомлений (10,000 операций).

## 2. Функциональное тестирование (Functional Tests)
*Проверка поведения подсистем в условиях, приближенных к реальным.*

*   **chaos_test.lua:**
    *   *Сценарии:* "Рекурсивная бомба" (события, вызывающие сами себя), "Блокирующий подписчик" (зависание одного обработчика).
    *   *Отказоустойчивость:* Проверка того, что система выживает при критических ошибках в пользовательском коде.
*   **core_ultra_test.lua:**
    *   *Сценарии:* Circuit Breaker (отключение сбойных подписчиков после N ошибок), защита от копирования циклических ссылок в событиях.
    *   *Стресс:* Проверка лимитов LVC (Burst Eviction) при шторме уникальных событий.
*   **dvb_ultra_test.lua:**
    *   *Сценарии:* Имитация дребезга сигнала (50 переключений Lock/Unlock в секунду), подача "мусорных" метрик (SNR=999, BER=-1).
    *   *Отказоустойчивость:* Проверка безопасности удаления занятых адаптеров.
*   **monitors_ultra_test.lua:**
    *   *Сценарии:* Массовое создание и удаление мониторов (Churn), имитация поврежденных структур данных от C-модулей Astra.
    *   *Стресс:* Проверка утечек памяти при интенсивном пересоздании объектов.
*   **resource_ultra_test.lua:**
    *   *Сценарии:* Имитация резких скачков CPU (0% -> 100%), повреждение файлов в `/proc`.
    *   *Адаптивность:* Проверка автоматического изменения интервалов опроса.

## 3. Стресс-тестирование (Stress Tests)
*Поиск пределов производительности и стабильности.*

*   **core_stress_test.lua:**
    *   *Шторм событий:* Эмиссия 5000+ событий с замером времени блокировки основного потока (Time-Slicing).
    *   *GC Pressure:* Проверка эффективности TablePool при 100,000 операциях в секунду (рост памяти должен быть < 1MB).
    *   *Load Shedding:* Верификация снижения нагрузки на систему при достижении критических порогов CPU.

## 4. Интеграционное тестирование (Integration Tests)
*Проверка взаимодействия модулей в едином цикле.*

*   **stability_integration_test.lua:**
    *   *Circle of Life:* Полный цикл данных: Планировщик -> Пул таблиц -> Эмиссия события -> Обработка подписчиком -> Возврат в пул.
    *   *Cascading Events:* Проверка цепочек реакций между независимыми модулями.
    *   *Churn Stability:* Устойчивость планировщика к постоянному пересозданию задач изнутри самих задач.

## 5. Инициализация
*   **check_init_monitor.lua:**
    *   *Проверка:* Полная загрузка библиотеки через `init_monitor.lua`, верификация регистрации всех 27+ внутренних модулей и их готовности к работе.
