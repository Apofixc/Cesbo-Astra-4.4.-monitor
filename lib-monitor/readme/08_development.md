# Разработка и стандарты

Библиотека `lib-monitor` следует строгим стандартам качества кода и тестирования, что гарантирует её стабильность в критических инфраструктурах.

## 1. Стандарты кода

*   **EmmyLua**: Весь код документирован с использованием аннотаций EmmyLua на русском языке. Это обеспечивает проверку типов и автодополнение в IDE.
*   **Astra Core Reference**: При разработке в качестве эталона используется исходный код Astra (Cesbo Astra). Любое взаимодействие с ядром должно соответствовать логике оригинальных модулей.
*   **Обработка ошибок**:
    *   Функции возвращают `data/true` при успехе и `nil/false` при ошибке.
    *   Все ошибки логируются через `Logger.error`.
    *   Использование `Logger.with_error` позволяет пробрасывать текст ошибки до HTTP-ответа.

## 2. Тестирование

Инфраструктура тестирования включает более 100 тест-кейсов, разделенных на уровни:

### Unit-тесты (`test/unit/`)
Проверка отдельных функций и методов классов в изоляции. Покрытие составляет 100% для всех 20 модулей библиотеки.

### Интеграционные тесты (`test/integration/`)
Проверка взаимодействия модулей (например, `EventDispatcher` + `SubscriptionManager` + `FilterEngine`).

### HTTP-тесты (`test/http/`)
Проверка корректности работы API, маршрутизации, аутентификации и форматов JSON-ответов.

### Функциональные тесты (`test/functional/`)
Запуск библиотеки в реальных условиях с использованием `tv3.lua` и реальных (или эмулируемых) медиа-потоков.

### Ultra-Extreme Suite
Специализированные тесты на выносливость:
*   **Chaos Test**: Случайное удаление и создание сотен мониторов в секунду.
*   **Stress Test**: Генерация миллионов событий для проверки пропускной способности шины.
*   **Sabotage Test**: Проверка устойчивости к некорректным данным из `/proc`, обрывам сетевых соединений и аппаратным сбоям тюнеров.

## 3. Запуск тестов

Для запуска всех тестов используйте скрипт:
```bash
/opt/astra/astra4.4.182 /opt/astra/lib-monitor/test/runner.lua
```

Для замера производительности:
```bash
/opt/astra/astra4.4.182 /opt/astra/lib-monitor/test/benchmark/unit/event_stress.lua
```

## 4. Профилирование и Оптимизация

При внесении изменений, влияющих на производительность, обязательно следовать правилу `performance-testing.md`:
1.  Замер метрик "До".
2.  Внесение изменений.
3.  Замер метрик "После" (минимум 100,000 итераций).
4.  Фиксация результатов в `test/benchmark/RESULTS.md`.
