# Справочник REST API

Все API-запросы требуют аутентификации с помощью заголовка `X-Api-Key`. Значение ключа устанавливается через переменную окружения `ASTRA_API_KEY` (по умолчанию "test").

## 1. Каналы (`/api/channels`)

Управление конфигурацией каналов Astra.

### GET `/api/channels`
*   **Описание**: Список всех каналов.
*   **Ответ**: `200 OK`, массив объектов с `name`, `display_name`, `output`.

### GET `/api/channels/stats`
*   **Описание**: Агрегированная статистика (всего, онлайн, оффлайн).

### GET `/api/channels/info`
*   **Описание**: Детальная конфигурация канала.
*   **Параметры**: `name` (Query или JSON).

### POST `/api/channels`
*   **Описание**: Создание нового канала.
*   **Тело**: JSON конфигурация канала.

### DELETE `/api/channels/kill`
*   **Описание**: Удаление или перезапуск канала.
*   **Параметры**: `name`, `reboot` (boolean).

## 2. Потоки с мониторингом (`/api/streams`)

Комбинированные операции (канал + монитор).

### POST `/api/streams`
*   **Описание**: Создание канала и сразу запуск его мониторинга.
*   **Тело**: JSON с полями канала и секцией `monitor`.

### DELETE `/api/streams/kill`
*   **Описание**: Удаление канала и связанного с ним монитора.

## 3. Мониторы (`/api/monitors`)

Управление активными экземплярами мониторов.

### GET `/api/monitors`
*   **Описание**: Список активных мониторов.

### GET `/api/monitors/data`
*   **Описание**: Текущие метрики конкретного монитора.
*   **Параметры**: `name`.

### PATCH `/api/monitors/update`
*   **Описание**: Динамическое обновление параметров (интервалы, пороги).

### POST `/api/monitors/pause` / `resume`
*   **Описание**: Приостановка и возобновление сбора метрик.

### GET `/api/monitors/pids`
*   **Описание**: Детальная статистика по всем PID в потоке (CC, PES, Bitrate).

## 4. DVB-адаптеры (`/api/dvb`)

Управление физическим оборудованием.

### GET `/api/dvb/hardware/all`
*   **Описание**: Список всех обнаруженных в системе DVB-адаптеров.

### POST `/api/dvb/adapters/tune`
*   **Описание**: Настройка адаптера на частоту и запуск мониторинга.
*   **Тело**: Параметры тюнера (`adapter`, `tp`, `lnb` и др.).

### POST `/api/dvb/adapters/switch-transponder`
*   **Описание**: Переключение частоты с сохранением зависимых каналов.

### GET `/api/dvb/adapters/data`
*   **Описание**: Метрики тюнера (Signal, SNR, BER, Lock).

## 5. Системные ресурсы (`/api/system`)

### GET `/api/system/health`
*   **Описание**: Полный отчет о состоянии: Astra, ресурсы, мониторы, сеть.

### GET `/api/system/api-stats`
*   **Описание**: Аналитика производительности API (время обработки, ошибки по роутам).

### POST `/api/system/reload` / `exit`
*   **Описание**: Управление процессом Astra.

## 6. Подписки (`/api/subscribers`)

### POST `/api/subscribers`
*   **Описание**: Регистрация нового Webhook.
*   **Тело**: `event_type`, `host`, `port`, `path`, `filters`, `throttle_ms`.

### DELETE `/api/subscribers`
*   **Описание**: Удаление подписки.

## Коды ответов

*   `200 OK`: Запрос успешно обработан.
*   `400 Bad Request`: Ошибка в параметрах или теле запроса.
*   `401 Unauthorized`: Отсутствует или неверен API-ключ.
*   `404 Not Found`: Ресурс (канал, монитор, адаптер) не найден.
*   `500 Internal Server Error`: Внутренняя ошибка при выполнении операции.
