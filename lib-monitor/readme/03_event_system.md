# Система событий и подписок

Шина событий (`EventDispatcher`) является центральной нервной системой `lib-monitor`. Она обеспечивает эффективную доставку метрик и уведомлений от мониторов к различным потребителям.

## 1. Event Dispatcher

Ядро системы, отвечающее за маршрутизацию событий.
*   **Приоритеты**: Поддержка уровней `LOW`, `MEDIUM`, `HIGH`. Критические события (например, `sys:resource_warning`) всегда обрабатываются первыми.
*   **Smart Emit (Hybrid Delivery)**: Интеллектуальный выбор пути доставки. Если подписчик не использует фильтры и троттлинг, событие доставляется мгновенно через **Direct Multicast**. Это снижает задержку на 30%.
*   **Load Shedding**: Автоматическая защита от перегрузок. При заполнении очередей система начинает отбрасывать низкоприоритетные события, сохраняя стабильность критических узлов.
*   **LVC (Last Value Cache)**: Кэширование последних состояний одновременно в виде Lua-таблиц и готовых JSON-строк. Это позволяет мгновенно инициализировать новых подписчиков без затрат на `json.encode`.

## 2. Subscription Manager

Управляет жизненным циклом подписок и их организацией.
*   **Decision Tree Routing**: Маски событий (Wildcards, например `channel:*`) организуются в дерево решений. Это позволяет находить всех подходящих подписчиков за один проход по строке типа события, независимо от их количества.
*   **Типы транспортов**:
    *   `HTTP (Webhooks)`: Отправка POST-запросов на внешние URL.
    *   `WebSocket`: Real-time стриминг событий.
    *   `Lua Callback`: Внутренняя обработка событий другими модулями.
    *   `Console`: Вывод событий в лог Astra.

## 3. Filter Engine

Мощный движок для фильтрации событий на стороне сервера.
*   **JIT-фильтрация**: Автоматическая компиляция условий фильтрации в оптимизированный Lua-код. Это исключает накладные расходы на парсинг условий при каждой отправке.
*   **Операторы**:
    *   Сравнение: `eq`, `ne`, `gt`, `lt`, `ge`, `le`.
    *   Строковые: `contains`, `matches` (regex).
    *   Множества: `in` (проверка наличия значения в списке).
*   **Сложные условия**: Поддержка логических групп `AND`/`OR` и вложенных полей (например, `data.cpu.usage`).
*   **Lua-скрипты**: Возможность написания произвольной логики фильтрации прямо в конфигурации подписки через поле `script`.

## 4. Троттлинг и Пакетная отправка

*   **Троттлинг (`throttle_ms`)**: Ограничение частоты отправки событий одного типа для конкретного подписчика. Позволяет не спамить уведомлениями при резких колебаниях метрик.
*   **Batching**: Группировка нескольких событий в один HTTP-запрос или WebSocket-пакет.
    *   `BatchMaxSize`: Максимальное количество событий в пачке.
    *   `BatchFlushInterval`: Максимальное время ожидания перед принудительной отправкой неполного батча.
*   **Retries**: Автоматическая переотправка HTTP-уведомлений при сбоях сети с использованием экспоненциальной задержки и джиттера (до 5 попыток).
