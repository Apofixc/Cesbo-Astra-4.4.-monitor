# Параметры конфигурации

Библиотека `lib-monitor` поддерживает гибкую настройку через файл `config.json`. Все параметры имеют значения по умолчанию, оптимизированные для большинства сценариев.

## 1. Логирование (`LogLevel`, `LogFormat`)

*   **`LogLevel`**: Уровень детализации логов (`DEBUG`, `INFO`, `WARN`, `ERROR`).
*   **`LogFormat`**: Формат вывода (`TEXT` или `JSON`).
*   **`LogBufferSize`**: Размер диагностического буфера логов для каждого компонента. Позволяет получать последние логи через API даже если они не были записаны в файл.

## 2. Сеть и HTTP

*   **`HttpTimeout`**: Таймаут для исходящих HTTP-запросов (Webhooks) в секундах.
*   **`RateLimitMaxRequests`**: Максимальное количество API-запросов от одного IP в течение окна `RateLimitWindow`.
*   **`MaxRetries`**: Количество попыток переотправки уведомлений при сетевых сбоях.

## 3. Лимиты мониторов

*   **`ChannelMonitorLimit`**: Максимальное количество одновременно активных мониторов каналов. Защищает от перегрузки CPU при массовом создании каналов.
*   **`DvbMonitorLimit`**: Лимит на количество мониторов DVB-адаптеров.
*   **`ForceSendInterval`**: Интервал (в итерациях), через который монитор обязан отправить свое состояние в шину событий, даже если метрики не изменились.

## 4. Системные ресурсы и Адаптивность

*   **`CpuThreshold`**: Порог загрузки CPU (%), при котором генерируется событие `sys:resource_warning`.
*   **`RamThresholdPct`**: Порог использования RAM Lua (%).
*   **`AdaptiveTickThresholdCpu`**: Порог CPU, при котором система переходит с `TickIntervalNormal` на `TickIntervalFast` для более частого опроса ресурсов.
*   **`MemoryLimitMb`**: Лимит памяти, при достижении которого планировщик начинает более агрессивно вызывать Garbage Collector.

## 5. События и Пакетная отправка

*   **`MaxQueueSize`**: Максимальный размер очереди событий. При переполнении включается механизм **Load Shedding**.
*   **`EventBatchLimit`**: Лимит количества событий, обрабатываемых за один тик планировщика. Позволяет распределять нагрузку во времени.
*   **`BatchMaxSize`**: Максимальный размер пачки событий для Webhooks и WebSocket.
*   **`BatchFlushInterval`**: Время (сек), через которое неполный батч будет отправлен принудительно.

## 6. Пулы и Кэши

*   **`MaxPoolSize`**: Максимальное количество таблиц в пуле одного типа. Увеличение этого значения снижает нагрузку на GC, но повышает потребление памяти.
*   **`MaxCacheSize`**: Лимиты для различных внутренних кэшей (Wildcards, FilterEngine).

## 7. Автоматическое восстановление

*   **`AutoRecoverEnabled`**: Если `true`, планировщик будет пытаться перезапустить мониторы, которые перестали обновлять данные (зависли).
*   **`AutoRecoverInterval`**: Время (сек), после которого монитор считается зависшим.
*   **`MaxRecoveryAttempts`**: Лимит попыток восстановления для одного объекта.
