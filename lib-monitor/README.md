# lib-monitor

`lib-monitor` — это библиотека Lua, которая служит точкой входа для системы мониторинга Astra (Cesbo), отвечая за инициализацию и загрузку всех ее компонентов. Она обеспечивает подключение основных утилит, адаптеров, модулей каналов, HTTP-сервера и диспетчеров мониторинга для полноценной работы системы. Библиотека предоставляет как программный интерфейс для автоматизации внутри Astra, так и полноценный HTTP REST API для интеграции с внешними системами.

## Основные возможности:

*   **Мониторинг DVB-тюнеров**: Инициализация, запуск, обновление параметров и получение детального статуса (Signal, SNR, BER, UNC, Quality). Автоматическое управление счетчиком каналов Astra для совместного использования адаптеров.
*   **Мониторинг каналов**: Создание, обновление, поиск и удаление мониторов для потоков каналов. Поддержка различных типов мониторов: `input` (вход), `output` (выход канала) и `ip` (прямой мониторинг UDP/RTP).
*   **Управление адресами мониторинга**: Установка и удаление адресов для автоматической отправки данных мониторинга клиентам (Push-метод/Webhooks).
*   **Отправка данных мониторинга**: Функция для рассылки собранных данных на настроенные адреса при изменении состояния.
*   **Валидация параметров**: Встроенные функции для строгой валидации имен и параметров мониторов на основе схем.
*   **Системный мониторинг**: Сбор метрик процесса Astra (CPU, RAM, Threads, FD) и всей системы (Disk I/O, Network I/O по интерфейсам, Load Average, Температура CPU).
*   **Гибкая конфигурация**: Поддержка различных методов сравнения состояния (Always, Strict, Ratio, On-Air) и настраиваемых порогов чувствительности.
*   **Интеграция с Astra**: Глубокое использование глобальных функций Astra для управления каналами, потоками и анализаторами.
*   **Логирование**: Интегрированное логирование с поддержкой контекстного хранения ошибок для передачи в HTTP-ответы.
*   **HTTP API**: Полноценный REST API для управления мониторами, каналами, тюнерами и получения PSI/SI данных.

## Установка:

Для использования `lib-monitor` необходимо скопировать содержимое репозитория в директорию `lib-monitor` вашего проекта Astra. Убедитесь, что все зависимости Lua установлены и доступны. Подключение в основном скрипте:
```lua
require("lib-monitor.init_monitor")
```

## Использование:

Библиотека предназначена для использования в проектах, требующих детального мониторинга DVB-тюнеров и потоков каналов. Ниже приведены основные функции, доступные глобально после инициализации:

### Функции для инициализации и управления сервером:

*   `server_start(addr, port)`: Запускает HTTP-сервер мониторинга. (Доступно через ModuleManager: `ModuleManager.get_module("http_server").start(addr, port)`)

### Функции для DVB-мониторинга:

*   `dvb_tuner_monitor(conf)`: Инициализация и запуск мониторинга DVB-тюнера. Параметр `conf` должен содержать конфигурацию тюнера (adapter, type, tp/frequency и др.).
*   `pause_dvb_monitor(name_adapter)`: Приостановка опроса тюнера.
*   `resume_dvb_monitor(name_adapter)`: Возобновление опроса тюнера.

### Функции для мониторинга каналов:

*   `make_stream(conf)`: Создание и запуск потока Astra с автоматической привязкой монитора. `conf` содержит параметры канала и секцию `monitor`.
*   `make_monitor(config, channel_data)`: Создание монитора для уже существующего объекта канала. `config` определяет параметры монитора, `channel_data` — данные о канале.
*   `kill_stream(name)`: Остановка потока и связанного с ним монитора.
*   `kill_monitor(name)`: Остановка и удаление только монитора.
*   `pause_monitor(name)`: Приостановка анализа потока.
*   `resume_monitor(name)`: Возобновление анализа потока.

### Функции для управления данными мониторинга (клиентские):

*   `set_client_monitoring(host, port, path, feed)`: Устанавливает или переопределяет адрес мониторинга для клиентов (Push-уведомления).
*   `remove_client_monitoring(host, port, path, feed)`: Удаляет конкретный адрес мониторинга для клиента.

## Методы получения данных мониторинга:

Библиотека `lib-monitor` поддерживает два основных метода получения данных мониторинга:

*   **Pull-метод (через HTTP API)**: Клиент отправляет HTTP GET-запросы к соответствующим API-эндпоинтам (например, `/api/monitors/{id}/data` или `/api/system/resources`) для получения актуальных данных. Этот метод подходит для периодического запроса информации по требованию.

*   **Push-метод (через подписку)**: Клиент может подписаться на получение данных мониторинга, используя функцию `set_client_monitoring` или API `/api/subscriptions/add`. В этом случае библиотека будет автоматически отправлять JSON-данные на настроенный адрес при их обновлении.

## API Endpoints:

Все API-запросы требуют аутентификации с помощью заголовка `X-Api-Key`. Значение ключа устанавливается через переменную окружения `ASTRA_API_KEY` (по умолчанию "test").

### Channel Routes (`/api/channels`)

*   **GET `/api/channels`**
    *   **Описание**: Получает список всех активных каналов.
    *   **Ответ**: JSON-объект со списком каналов (ID, имя, выходы).

*   **GET `/api/channels/stats`**
    *   **Описание**: Возвращает агрегированную статистику по всем каналам.
    *   **Ответ**: `{"total": 10, "online": 8, "offline": 2, "with_errors": 1}`.

*   **GET `/api/channels/{id}`**
    *   **Описание**: Возвращает детальную конфигурацию канала.
    *   **Ответ**: JSON-объект с параметрами `input`, `output`, `map`.

*   **GET `/api/channels/{id}/inputs`**
    *   **Описание**: Возвращает список входов канала и индекс активного входа.
    *   **Ответ**: `{"inputs": [...], "active_input": 1}`.

*   **GET `/api/channels/{id}/psi`**
    *   **Описание**: Получает данные PSI/SI канала (PMT, SDT).
    *   **Ответ**: JSON-объект с таблицами PSI.

*   **POST `/api/channels/create`**
    *   **Описание**: Создает новый канал.
    *   **Параметры (JSON)**: Стандартная конфигурация канала Astra.

*   **POST `/api/channels/{id}/kill`**
    *   **Описание**: Останавливает или перезагружает канал.
    *   **Параметры (Query)**: `reboot` (boolean, опционально).

### DVB Routes (`/api/dvb`)

*   **GET `/api/dvb/adapters`**
    *   **Описание**: Получает список активных DVB-адаптеров.
    *   **Ответ**: JSON-массив объектов адаптеров.

*   **GET `/api/dvb/adapters/{id}/data`**
    *   **Описание**: Получает текущие метрики DVB-адаптера.
    *   **Ответ**:
```json
        {
          "adapter_data": {
            "id": "dvb0",
            "status": 1,
            "signal": 75.5,
            "snr": 24.8,
            "ber": 0,
            "unc": 0,
            "quality": 100,
            "lock": true
          }
        }
```

*   **GET `/api/dvb/adapters/{id}/psi`**
    *   **Описание**: Сбор и получение PSI данных напрямую с частоты адаптера.

*   **POST `/api/dvb/adapters/{id}/tune`**
    *   **Описание**: Перенастройка адаптера на новую частоту.
    *   **Параметры (JSON/Query)**: `tp` (string, обязательно).

*   **POST `/api/dvb/adapters/{id}/update`**
    *   **Описание**: Обновляет параметры мониторинга адаптера (rate, time_check).

*   **POST `/api/dvb/scan`**
    *   **Описание**: Запуск процесса сканирования частот.

### Monitor Routes (`/api/monitors`)

*   **GET `/api/monitors`**
    *   **Описание**: Возвращает список всех активных мониторов (Channel + DVB).

*   **GET `/api/monitors/status`**
    *   **Описание**: Возвращает сводный статус по всем мониторам.
    *   **Ответ**: `{"total": 20, "ok": 18, "error": 2, "total_cc_errors": 150}`.

*   **GET `/api/monitors/{id}/data`**
    *   **Описание**: Возвращает текущие метрики конкретного монитора.
    *   **Ответ**:
```json
        {
          "monitor_data": {
            "id": "Discovery",
            "status": "OK",
            "bitrate": 12500,
            "cc_errors": 0,
            "pes_errors": 0,
            "scrambled": false,
            "ready": true
          }
        }
```

*   **POST `/api/monitors/{id}/update`**
    *   **Описание**: Динамическое обновление параметров монитора.
    *   **Параметры**: `rate`, `time_check`, `method_comparison`, `analyze`.

### Subscriber Routes (`/api/subscriptions`)

*   **GET `/api/subscriptions`**
    *   **Описание**: Возвращает список всех активных получателей Push-уведомлений.

*   **POST `/api/subscriptions/add`**
    *   **Описание**: Добавляет новую подписку.
    *   **Параметры**: `event_type` (channels, dvb, error), `host`, `port`, `path`.

*   **POST `/api/subscriptions/remove`**
    *   **Описание**: Удаляет существующую подписку.

### System Routes (`/api/system`)

*   **GET `/api/system/env`**
    *   **Описание**: Информация о версии Astra и аптайме процесса.

*   **GET `/api/system/resources`**
    *   **Описание**: Получает детальные данные о системных ресурсах.
    *   **Ответ**:
```json
        {
          "resources": {
            "cpu": { "total": 12.5, "user": 8.0, "sys": 4.5, "temp_c": 45.0 },
            "memory": { "rss_kb": 262809, "vms_kb": 512000, "lua_kb": 1500 },
            "io": { "read_bps": 1024, "write_bps": 512 },
            "network": { "eth0": { "rx_bps": 1250000, "tx_bps": 750000 } },
            "system": { "load_avg": [0.5, 0.8, 1.2], "fd_count": 120 }
          }
        }
```

*   **GET `/api/system/health`**
    *   **Описание**: Проверка работоспособности сервера.

*   **GET `/api/system/monitor-stats`**
    *   **Описание**: Статистика работы модуля `ResourceMonitor`.

*   **POST `/api/system/reload`**
    *   **Описание**: Мягкая перезагрузка процесса Astra.

*   **POST `/api/system/exit`**
    *   **Описание**: Завершение работы Astra.

*   **POST `/api/system/clear-cache`**
    *   **Описание**: Очистка кэша системных метрик.

## Методы сравнения состояния:

Библиотека использует параметр `method_comparison` для оптимизации отправки данных:
1.  **Always (1)**: Отправка данных при каждом обновлении от Astra.
2.  **Strict (2)**: Отправка при любом изменении статуса, битрейта или появлении ошибок CC/PES.
3.  **Ratio (3)**: Отправка при изменении статуса или если отклонение битрейта превысило порог `rate` (по умолчанию 0.035 или 3.5%).
4.  **On-Air (4)**: Отправка только при изменении флага наличия сигнала (On-Air).

## Пример использования в коде:

```lua
-- Инициализация
require("lib-monitor.init_monitor")

-- Запуск API сервера
local ModuleManager = require("lib-monitor.src.module_manager")
local server = ModuleManager.get_module("http_server")
server.start("0.0.0.0", 8080)

-- Создание стрима с мониторингом
make_stream({
    name = "Discovery",
    input = {"http://example.com/stream.ts"},
    output = {"udp://239.255.1.1:1234"},
    monitor = {
        monitor_type = "output",
        method_comparison = 3,
        rate = 0.05,
        analyze = true
    }
})

-- Мониторинг DVB адаптера
dvb_tuner_monitor({
    name_adapter = "dvb0",
    type = "S2",
    adapter = 0,
    tp = "11044:V:43200",
    time_check = 10
})
```
